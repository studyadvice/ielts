01 基礎

最小可用範例

只需三個屬性：quiz、answer、correct-next。 選項使用 <ir-choices> 包覆，每個選項是 <ir-choice value="…">。 答對後自動跳轉，答錯則提示但留在原題。

HTML 
<info-region
  id="s1-q1"
  quiz
  answer="b"
  correct-next="s1-done"
  active="true"
>
  <p>HTTP 是哪種協定？</p>
  <ir-choices>
    <ir-choice value="a">有狀態</ir-choice>
    <ir-choice value="b">無狀態</ir-choice>
    <ir-choice value="c">串流</ir-choice>
  </ir-choices>
</info-region>

<info-region id="s1-done" color="safe">
  完成！
</info-region>
預覽

HTTP 是哪種協定？

有狀態（Stateful） 無狀態（Stateless） 串流（Streaming）

✓ 完成！
quiz布林屬性，啟動測驗模式。加上即生效，無需賦值。
answer="b"正確答案的 value 值，不分大小寫。
correct-next="…"答對後自動啟動的目標元素 id。若省略，答對後停留原處。
💡 省略 wrong-next 時，答錯只顯示標記，不跳轉。適合「多試幾次」的情境。
02 基礎

自訂訊息與解說文字

correct-msg、wrong-msg 控制答題後的前綴訊息； explain 追加解說說明，兩者都會在選項下方以動畫浮現。

HTML 
<info-region
  id="s2-q1"
  quiz
  answer="c"
  correct-next="s2-done"
  correct-msg="✓ 完全正確！"
  wrong-msg="✗ 再想一下…"
  explain="DNS 負責將網域名稱
           解析為 IP 位址。"
  active="true"
>
  …
</info-region>
預覽

DNS 的主要功能是什麼？

傳送電子郵件 加密網路流量 將網域名稱解析為 IP 位址 動態分配 IP 給裝置

✓ 答對了！
correct-msg="…"答對時顯示在解說區塊最前面的訊息。預設：「✓ 答對了！」
wrong-msg="…"答錯時顯示的訊息。預設：「✗ 答錯了。」
explain="…"訊息之後追加的解說文字，答對/答錯都會顯示。
03 基礎

手動繼續按鈕

預設答題後自動跳題（延遲 1200ms）。加上 manual-next 改為顯示按鈕， 使用者閱讀完解說後自行點擊繼續。quiz-next-label 自訂按鈕文字。

HTML 
<info-region
  id="s3-q1"
  quiz
  answer="b"
  correct-next="s3-done"
  explain="O(1) 均攤，
    動態陣列末尾擴充。"
  manual-next
  quiz-next-label="我了解了，繼續 ▶"
  quiz-next-delay="800"
  active="true"
>…</info-region>

<!-- manual-next 不存在時：
     答題後等 quiz-next-delay ms
     自動跳到 correct/wrong-next  -->
預覽

Python list.append(x) 的時間複雜度？

O(n) O(1) 均攤 O(log n)

✓ 完成！
manual-next布林屬性。加上後改為按鈕繼續，省略則自動跳題。
quiz-next-label="…"繼續按鈕的文字。預設「繼續 ▶」。
quiz-next-delay="1200"自動跳題的延遲（ms）。只有省略 manual-next 時有效。
04 中級

多題串接

每道題只需宣告自己的 correct-next，元件自動串聯。 搭配 <info-region-group> 統一管理開始/重設，並加上題號標籤。

HTML 
<info-region-group
  auto-start
  show-controls
>

  <info-region
    id="q1"
    quiz
    quiz-label="第 1 題 / 共 2 題"
    answer="b"
    correct-next="q2"
    manual-next
  >…</info-region>

  <info-region
    id="q2"
    quiz
    quiz-label="第 2 題 / 共 2 題"
    answer="a"
    correct-next="q-end"
    manual-next
  >…</info-region>

  <info-region id="q-end"
    color="safe">
    全部完成！
  </info-region>

</info-region-group>

quiz-label="…"顯示在題目左上角的小標，常用作題號提示。
auto-start掛在 group 上，頁面載入後自動啟動第一個子區塊。
show-controls掛在 group 上，顯示「開始」與「重設」按鈕。
05 中級

答錯解說再繼續

wrong-next 指向一個解說型 <info-region>， 解說完自動或手動跳回主線。解說區塊本身不需要 quiz，用 countdown 自動進入下一題。

題目 Q → 答對   next-Q 題目 Q → 答錯   解說區塊 → countdown next-Q
HTML 
<!-- 題目區塊 -->
<info-region
  id="q1"
  quiz
  answer="b"
  correct-next="q2"
  wrong-next="q1-explain"
  manual-next
>…</info-region>

<!-- 解說區塊（無 quiz，用 countdown）-->
<info-region
  id="q1-explain"
  color="warning"
  next="q2"
  countdown="3000"
  countdown-color="warning"
>
  <p>解說文字…</p>
</info-region>
預覽

JavaScript 中，0.1 + 0.2 === 0.3 的結果？

true false 取決於執行環境

浮點數陷阱

IEEE 754 浮點數無法精確表示 0.1 與 0.2，相加結果為 0.30000000000000004，因此 === 0.3 為 false。3 秒後繼續…

✓ 完成！
✦ 解說區塊不加 quiz-item 屬性，進度條就不會把它計入題目總數。
06 中級

答錯重試

wrong-next 指向自己的 id，答錯後選項解鎖，讓使用者重新選答。 計分板只在第一次答錯時計入 wrong 計數，重試成功不重複計錯。

題目 Q → 答對 next 題目 Q → 答錯 題目 Q（自身） → 答對 next
HTML 
<info-region
  id="q1"
  quiz
  answer="c"
  correct-next="done"
  wrong-next="q1"
              ↑ 指回自身 id
  wrong-msg="✗ 再試一次！"
  manual-next
>…</info-region>
預覽

✓ 完成！
⚠ 重試時，_quizAnswered 旗標會被 reset() 清除，選項全部解鎖。但 group 的 _answeredSet 記錄「曾答對過」，進度條不因重試倒退。
07 進階

進度條與計分板

在 <info-region-group> 加上 global-progress 顯示進度條， 加上 show-score 顯示計分板。 題目型區塊標記 quiz-item，讓進度條只統計題目數量，不把解說區塊算進去。

HTML 
<info-region-group
  global-progress
  progress-position="top"
  progress-color="sky"
  show-percent
  show-score
  auto-start
  show-controls
>

  <!-- ★ 加 quiz-item 屬性 -->
  <info-region
    id="q1"
    quiz
    quiz-item
    answer="b"
    correct-next="q2"
    wrong-next="q1-exp"
    manual-next
  >…</info-region>

  <!-- 解說區塊：不加 quiz-item -->
  <info-region
    id="q1-exp"
    color="warning"
    next="q2"
    countdown="3000"
  >…</info-region>

</info-region-group>
預覽

const 宣告後可以…？

自由重新賦值 修改物件屬性，但不能重新賦值 完全不可更改 只能在函式內使用

提示

const 防止的是「重新賦值（rebind）」，不是「變動（mutation）」。3 秒後繼續。

let 與 var 的主要差異？

let 是區塊作用域，var 是函式作用域 let 可以被 hoisting，var 不行 兩者完全相同，只是命名不同

測驗完成！查看上方計分板。
global-progress掛在 group，顯示全域進度條。
progress-position="top"進度條位置。"top" 或 "bottom"。
show-percent在進度條旁顯示百分比數字。
show-score顯示答對 / 答錯 / 總題數計分板。
quiz-item標記此題目型區塊，進度條以此計算分母，排除解說區塊。
08 進階

依答案分歧路由

correct-next 和 wrong-next 各自有獨立的後續節點， 形成真正的分歧流程圖。兩條路線可以在任意節點匯聚，也可以各自結束。

入口題 → 答對 進階路 A1 → A2 入口題 基礎路 B1 → B2 → 匯聚 結尾 x x x → 匯聚 結尾
HTML 
<!-- 入口分流題 -->
<info-region
  id="entry"
  quiz  answer="a"
  correct-next="hard-q1"
  wrong-next="easy-q1"
  manual-next
>…</info-region>

<!-- 進階路線：有自己的 correct/wrong-next -->
<info-region
  id="hard-q1"
  quiz  answer="b"
  correct-next="finish"
  wrong-next="finish"
  manual-next
>…</info-region>

<!-- 基礎路線：同樣有自己的 next -->
<info-region
  id="easy-q1"
  quiz  answer="c"
  correct-next="finish"
  wrong-next="finish"
  manual-next
>…</info-region>

<!-- 匯聚終點 -->
<info-region id="finish"
  color="special">
  完成！
</info-region>
預覽

關鍵設計原則：每個節點只認識自己的下一步，不需要知道整條路線的存在。 新增或調整路線只需要修改當下節點的 correct-next 或 wrong-next，其他節點零影響。

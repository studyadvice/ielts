ink-pen 極簡畫筆層

螢幕錄影時的最小標註工具。只保留觸控筆、雷射筆、筆跡色彩、清除與收合，工具列預設是右下角一顆 40px 的小圓鈕，不會壓到錄影主體區。零依賴，單獨一支 js 丟進任何頁面就能用。

Personally, I don't think technology has made people read less; it has reshaped the way we read. On my commute I'll quite happily work through a long article on my phone, but when it comes to digesting an entire book, I still fall back on print.

錄影時的小圓鈕狀態

  • 圓鈕中心的小點會顯示目前筆色，一眼就知道待會畫出來是什麼顏色。
  • 筆或雷射作用中時，圓鈕外圈會亮起海洋藍光暈，提醒你此時頁面無法點選。
  • 工具列收合後，1、3、0、C 仍然有效，所以整段錄影其實可以不展開工具列。

筆跡色彩與粗細

下拉選單內建八個顏色，都取自既有配色表。雷射筆固定使用警示紅，不受這裡影響。

v2　10-28-26

新增 data-anchor 座標模式，筆跡可選擇固定在視窗或跟著內容捲動；新增 extra-color 自訂筆色。

座標模式　data-anchor

viewport　貼著視窗（預設）

筆跡以螢幕座標記錄，捲動頁面時筆跡留在原本的螢幕位置。適合畫面固定不動的錄影，或在單一畫面上做框線、箭頭這類不屬於某段文字的標記。

觸控時會完全鎖住捲動（touch-action:none），下筆最穩。

document　貼著內容

筆跡以文件座標記錄，捲動頁面時筆跡跟著段落一起移動，可以邊捲邊畫，整頁講解完回頭捲上去，前面劃的線還在原來的句子上。

觸控時放行垂直捲動（touch-action:pan-y），用觸控筆橫向劃線、用手指上下捲；滑鼠滾輪在兩種模式下都能捲。

實際比較

按 1 開筆，在下面三個色塊上各畫一條線，然後捲動頁面看看筆跡的行為；再切換模式重畫一次。切換當下畫面上的筆跡位置不會跳動，元件會依當時的捲動量換算座標。

自訂筆色　extra-color

用法

在工具列加上 extra-color，色彩選單尾端就會多一個選項，並在載入時自動選用它。extra-label 可指定顯示名稱，省略時直接顯示色碼。

接受 #RGB 與 #RRGGBB 兩種寫法，格式不符會跳出警示並沿用內建色彩，不會中斷其他功能。

目前自訂色：#FFFFFF

v2 標籤寫法

<ui-ink-bar
    data-pos="br"
    extra-color="#FFFFFF"
    extra-label="純白 white"></ui-ink-bar>

// 座標模式，兩邊都可以叫
InkPen.layer().setAnchor('document');

v3　10-28-26

新增 <ink-handwrite> 行內手寫空格：底線長度決定空格寬度，點一下開手寫視窗，確認後筆跡填回空格。

行內手寫空格　ink-handwrite

直接試寫

每個空格都是獨立的。點空格上的筆圖示開啟手寫視窗，寫完按確認填入；再點一次會從空白開始重寫，不會接續上次的筆跡。確認時若畫布是空的，等同清空該空格。

我想談談書法，那是我在暑假期間開始學的。 I'd like to talk about ___________, which I _________ during the summer break.

那條老街的窄巷裡飄著麻油與線香的氣味。 The narrow lanes are __________ the smell of sesame oil and _______.

多數人最後待得比原本計畫的久很多。 Most of them ________ staying far _____ than planned, and nobody _______________ about it.

每次確認填入都會在這裡留下紀錄，由 ink-written 事件提供。
觸控筆或雷射筆開啟時，繪圖層會蓋住整頁，此時空格點不到。先按 0 關閉繪圖再點空格，這也是刻意的：錄影中在空格上劃線與開手寫視窗是兩件不同的事。

寬度怎麼決定

元件讀取標籤內的底線數量，可辨識 5 到 15 個，不足 5 個補到 5，超過 15 個收到 15。寬度以 ch 計算，所以會跟著周圍文字的字級縮放，長句換行時空格也會一起排版。

也可以用 data-slots="12" 直接指定格數，此時標籤內容寫什麼都不影響。全形底線 ＿ 同樣可辨識。

筆跡怎麼塞進空格

手寫視窗的畫布會依照目標空格的長寬比調整，所以寫出來的字比例和填回去的樣子接近。

確認時元件只取筆跡的最小外框再輸出 PNG，寫在畫布哪個位置都沒關係，不會在空格裡留下一大片空白。視窗內的筆較粗，預設 10 px、範圍 4 至 24，因為縮小後線條會變細。

v3 新增介面

// 單一空格
var blank = document.querySelector('ink-handwrite');
blank.slots;          // 格數 5 至 15
blank.hasInk();       // 是否已填入
blank.getInk();       // PNG 的 dataURL 或 null
blank.setInk(url);    // 直接塞入既有筆跡
blank.clearInk();     // 清空

// 整頁
InkPen.blanks();      // 所有 <ink-handwrite>
InkPen.clearBlanks(); // 全部清空
InkPen.modal();       // 取得手寫視窗

// 每次確認填入都會冒泡一個事件
document.addEventListener('ink-written', function (e) {
  e.detail.el;        // 哪個空格
  e.detail.dataUrl;   // 筆跡圖，清空時為 null
  e.detail.empty;     // 是否為清空
  e.detail.slots;     // 該空格的格數
});

設計取捨

為什麼預設仍是視窗座標

錄影時畫面多半固定不動，視窗座標的運算最少，觸控也能完全鎖住捲動，下筆不會誤觸發頁面滑動。需要長篇講解再切 document。

為什麼手寫視窗每次從空白開始

照你的規格做。教學現場的實際需求是「寫錯就重來」，若保留上次筆跡，你得先判斷哪幾筆要留、哪幾筆要擦，反而比重寫一次慢。

為什麼筆跡存成圖片

空格裡只需要顯示結果，存成裁切後的 PNG 最單純，可以直接塞進任何版面、跟著文字換行。需要原始點序列再另外擴充即可。

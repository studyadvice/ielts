測驗模式使用說明 · data-ir-ans 揭曉答案 · 自評式 flashcard 流程
核心概念

測驗模式在原有 info-region 架構上疊加一套互動流程，完全不改動現有屬性。 啟用方式有兩種：

啟用方式 說明
quiz（加在 <info-region>） 單一 region 啟用測驗行為，可鏈接 next 形成獨立問答序列
quiz-mode（加在 <info-region-group>） 群組內所有 region 皆進入測驗模式，由 group 統一管理流程、計分與進度

答案寫在 region 內部的子元素，並加上 data-ir-ans 屬性。 元件自動將它收合，等使用者點「揭曉答案」才展開。 

<!-- 基本結構 -->
<info-region quiz color="lavender">

  <!-- 題目：直接放在 region 裡面 -->
  <p>CSS 的 em 和 rem 有何差異？</p>

  <!-- 答案：加上 data-ir-ans，預設收合 -->
  <div data-ir-ans>
    <strong>em</strong> 相對於父元素字體大小；
    <strong>rem</strong> 相對於根元素（html）字體大小，不受巢狀影響。
  </div>

</info-region>
新增屬性一覽 NEW

加在 <info-region> 上：

屬性預設值說明
quiz （旗標） 啟用單一 region 測驗行為，覆蓋 countdown / manual
quiz-reveal-label "👁 揭曉答案" 揭曉按鈕的文字
quiz-reveal-color 繼承 color 揭曉按鈕的品牌色名稱
quiz-ok-label "✓ 記住了" 答對按鈕文字
quiz-retry-label "↺ 再看一次" 答錯按鈕文字
quiz-ok-color "safe" 答對按鈕品牌色
quiz-retry-color "warning" 答錯按鈕品牌色
quiz-continue-label "▶ 繼續" 無答案元素時的推進按鈕文字（純說明頁）

加在 <info-region-group> 上：

屬性預設值說明
quiz-mode （旗標） 群組測驗模式；group 接管流程，停用 cascade / manual
quiz-score （旗標） 顯示即時得分列（✓ n / m 題答對 k%）
quiz-shuffle （旗標） 每次開始時隨機打亂題目順序
quiz-retry-at-end （旗標） 完成後顯示「只複習 N 題」按鈕，針對標記錯誤的題目重練
quiz-keep-all （旗標） 答完不收起前一題，所有已答題目累積顯示（flashcard 堆疊效果）
quiz-complete-title "🎉 測驗完成！" 完成訊息框的標題文字

InfoRegionConfig 全域預設值（可在載入 js 前覆蓋）： 

// 在 <script src="info-region.js"> 之前設定
window.InfoRegionConfig = {
  quizRevealLabel:   '👁 揭曉答案',
  quizRevealColor:   null,        // null = 繼承 region color
  quizOkLabel:       '✓ 記住了',
  quizRetryLabel:    '↺ 再看一次',
  quizOkColor:       'safe',
  quizRetryColor:    'warning',
  quizContinueLabel: '▶ 繼續',
  quizCompleteTitle: '🎉 測驗完成！',
};
範例 A　獨立 quiz region

不需要 group，直接在 region 上加 quiz 屬性，並用 next 鏈接下一題。 適合在文章中插入零散的隨堂問答。 

<info-region id="qa1" quiz color="lavender" next="qa2" active="true">
  <p><strong>Q1</strong>  HTTP 的 GET 和 POST 最主要的差異是什麼？</p>
  <div data-ir-ans>
    GET 把參數放在 URL；POST 放在 request body。
    GET 適合讀取，POST 適合傳送敏感或大量資料。
  </div>
</info-region>

題 1 / 3

Q1  HTTP 的 GET 和 POST 最主要的差異是什麼？

GET 把參數放在 URL 查詢字串；POST 放在 request body，較適合傳送敏感或大量資料。GET 是冪等（idempotent）操作，POST 不一定。
題 2 / 3

Q2  什麼是 CSS 的 BEM 命名規則？

Block、Element、Modifier。
例：.card__title--highlighted。
用雙底線區隔區塊與元素，雙連字號區隔修飾語。
題 3 / 3

Q3  JavaScript 的 == 與 === 有何不同？

== 做型別強制轉換後比較（loose equality）；=== 型別與值都必須相同（strict equality）。日常推薦使用 ===。

資料結構

Stack（堆疊）和 Queue（佇列）最主要的行為差異是什麼？

Stack 遵循 LIFO（後進先出）；Queue 遵循 FIFO（先進先出）。 Stack 常用於函式呼叫堆疊、undo 操作；Queue 常用於任務排程、BFS 演算法。
網路

DNS 的主要功能是什麼？

Domain Name System：將人類可讀的網域名稱（如 google.com）解析為 IP 位址，讓瀏覽器能找到目標伺服器。
SQL

INNER JOIN 和 LEFT JOIN 的結果有什麼不同？

INNER JOIN 只回傳兩表都有對應資料的列； LEFT JOIN 保留左表所有列，右表無對應則以 NULL 填充。
Python

Python 的 list 和 tuple 有何核心差異？

list 可變（mutable），支援新增、刪除、修改； tuple 不可變（immutable），建立後無法修改，因此執行效率略優，常用於不應被改動的資料。

HTTP 狀態碼 404 代表什麼？

Not Found。伺服器無法找到請求的資源，通常是 URL 不正確或資源已被刪除。

什麼是 SQL Injection？

攻擊者在輸入欄位插入惡意 SQL 語句，導致資料庫執行非預期的查詢或命令。 防禦方式：使用 Prepared Statements（參數化查詢）。

解釋 CSS position: sticky 的行為。

在正常文件流中定位，一旦滾動到達設定的臨界點（如 top: 0），就固定在該位置，直到其父容器滾出視口為止。

Git 的 rebase 和 merge 各適合什麼情境？

merge 保留完整歷史與分支結構，適合協作主分支； rebase 重寫提交歷史為線性，讓 log 更乾淨，適合個人功能分支整合前。

什麼是 REST API 的 stateless 特性？

每個請求必須包含處理該請求所需的所有資訊，伺服器不儲存客戶端的 session 狀態。 好處：易於水平擴展、提高可靠性。

Promise 的三種狀態是什麼？

Pending（等待中）→ Fulfilled（已完成）或 Rejected（已拒絕）。 一旦從 pending 轉換，狀態就不可再變更。

async/await 是什麼的語法糖？

是 Promise 的語法糖，讓非同步程式碼看起來像同步寫法， 提升可讀性。await 只能在 async 函式內使用。

info-region 使用手冊

涵蓋 info-region.js 的全部標籤、屬性、設定與 API。每個行為都已實際執行驗證，搭配 info-region-demo-10-24-26.html 食用最佳。

0. 這份手冊在講什麼

info-region.js 提供一組「逐步揭露內容」的元件：區塊一開始是隱藏的，被啟用後以動畫展開，並可依設定自動、倒數、手動或透過測驗答題，接著啟用下一個區塊。它也能把多個區塊放進群組，加上進度條、計分板與「開始、重設」按鈕。

標籤角色
<info-region>單一區塊。可顯示說明文字、當作測驗題、當作倒數或手動繼續的節點。
<info-region-group>群組容器。提供開始與重設按鈕、橫向排版、逐一顯示、全域進度條、計分板。
<ir-choices>測驗選項的容器，純語意標籤。
<ir-choice>單一測驗選項，以 value 屬性對應答案。
項目內容
檔案info-region.js，獨立 .js，使用 Custom Elements，不使用 shadow DOM，樣式由 js 自行注入。
相依無。不需要 Bootstrap 或任何函式庫。
載入位置放在頁面底部（</body> 之前）。群組在建立時會去找自己的子區塊，放在 head 載入可能讓群組在子區塊還沒解析完時就開始建構。
全域設定window.InfoRegionConfig 必須在 info-region.js 之前定義，載入後再改無效（第 10 節）。
示範頁info-region-demo-10-24-26.html，與本手冊各章對應，每個範例旁都附原始碼。
本手冊對應版本你於 2026-10-24 提供的 info-region.js（1218 行）。
提示：本手冊所有「行為」描述，都已在模擬環境中實際執行驗證，並非只讀程式碼推測。少數只靠讀碼判斷、未實測的地方，會明確標示「讀碼所得」。

1. 快速開始

1.1 自動揭露：三個區塊依序出現

<info-region id="a" active="true" next="b">
  <h5>第一步</h5>
  <p>這個區塊一載入就展開。</p>
</info-region>

<info-region id="b" next="c" color="ocean">
  <p>0.5 秒後自動展開，因為 a 指定了 next="b"。</p>
</info-region>

<info-region id="c" color="teal">
  <p>最後一個，沒有 next，鏈到此結束。</p>
</info-region>

<script src="info-region.js"></script>

只有第一個區塊寫 active="true"，其餘由 next 串起來。每個區塊的左邊框顏色由 color 決定，沒寫則是預設的 sky。

1.2 手動繼續

<info-region id="m1" active="true" manual next="m2">
  <p>讀完按按鈕才會出現下一段。</p>
</info-region>
<info-region id="m2">
  <p>下一段。</p>
</info-region>

1.3 選擇題

<info-region id="q1" quiz answer="c" active="true"
             correct-next="q1-ok" explain="逗號加 which 可以接結果。">
  <p>Traffic is bad, ________ I leave home early.</p>
  <ir-choices layout="column">
    <ir-choice value="a">except for</ir-choice>
    <ir-choice value="b">as a result</ir-choice>
    <ir-choice value="c">which is why</ir-choice>
  </ir-choices>
</info-region>
<info-region id="q1-ok" color="safe"><p>答對後出現的補充說明。</p></info-region>

1.4 群組：開始與重設按鈕，加上進度條

<info-region-group global-progress show-percent cascade-interval="600">
  <info-region>第一段</info-region>
  <info-region>第二段</info-region>
  <info-region>第三段</info-region>
</info-region-group>

群組會在最上方自動長出「開始、重設」按鈕。按開始後，每隔 600 毫秒顯示一段，進度條同步前進。

2. 核心觀念：啟用與推進的決策順序

一個區塊有兩種狀態：隱藏（高度為 0、透明、不佔位置）與啟用（active="true"，展開並可互動）。區塊被啟用的那一刻，元件依下表由上往下判斷「接下來做什麼」，命中第一個就停止，下面的都不看。

順序條件行為詳見
1區塊有 quiz 屬性進入測驗模式。此區塊的 next、countdown、manual 全部被忽略，由答題結果決定下一個區塊。第 7 節
2區塊有 manual 且有 next在區塊底部插入手動按鈕，按下才啟用 next。第 4 節
3區塊所在群組有 global-progress，或群組的 cascade-interval 大於 0什麼都不做。這種群組的推進交給群組本身（逐一顯示）、測驗或手動按鈕。第 8 節
4區塊有 countdown顯示倒數條，時間到後啟用 next。第 4 節
5以上都不是等 next-interval 毫秒後啟用 next。第 4 節
注意：第 3 條最容易踩雷：在有 global-progress 的群組裡，區塊的 next 與 countdown 不會推進（實測：只有第一個區塊亮起，進度停在 33%）。這種群組請搭配 cascade-interval、manual 或 quiz，或用程式呼叫 activate()。

啟用的幾個細節

  • 只有 active 屬性的值恰好是字串 true 才算啟用，active="false" 或其他值不會啟用。
  • 對已經啟用的區塊再次 setAttribute("active", "true") 或呼叫 activate()，不會有任何作用。要重新播放，先 reset() 再 activate()。
  • 隱藏的區塊在垂直排列時完全不佔空間；啟用後才佔位並加上 margin-bottom。在橫向群組中則始終佔位（透明），版面不會跳動。
  • 啟用狀態下區塊最大高度為 4000px，更長的內容會被裁切。
  • 寫在 HTML 裡一開始就 active="true" 的區塊，啟動流程實測會執行兩次（一次在元件升級時、一次在連接到頁面後的下一個動畫影格）。元件對各流程都有防重複處理，結果不受影響，知道即可。

3. info-region 屬性總表

全部寫在 <info-region> 標籤上。布林屬性只要寫出屬性名稱即可（例如 manual、quiz、show-retry）。數值類屬性寫整數，單位固定，不要加單位文字。

3.1 基本與外觀

HTML 屬性預設值說明
id無強烈建議每個區塊都寫。next 指向它、測驗計分都靠 id。
active無值為 true 時啟用。通常只有第一個區塊寫，其餘由推進機制啟用。
colorsky色票名稱（第 12 節）。決定邊框顏色，也是倒數條與各種按鈕的預設顏色。不認得的名稱，邊框退回 sky，按鈕則沒有配色。可動態修改，啟用中修改會立即生效。
class="ir-gold"無金箔特別版外觀，用於開場或結尾，見第 6 節。
border-width見第 5 節四邊邊框寬度（整數 px）。
border-top-width、border-right-width、border-bottom-width、border-left-width見第 5 節單邊寬度，優先於 border-width。
border-stylesolid四邊邊框樣式。
border-top-style、border-right-style、border-bottom-style、border-left-style見第 5 節單邊樣式，優先於 border-style。

3.2 自動、倒數、手動推進

HTML 屬性預設值說明

countdown-height3倒數條高度（整數 px）。

manual-color同 color按鈕顏色（色票名稱）。
manual-alignright按鈕位置：left、center、right。

HTML 屬性預設值說明
quiz無把這個區塊變成選擇題。區塊內需要有 <ir-choices>。
answer無正確選項的 value。比對時忽略大小寫與前後空白。
correct-next無答對後啟用的區塊 id。
wrong-next無答錯後啟用的區塊 id。沒寫時，答錯就是終點，不會推進。
quiz-next-delay1200答題後等多少毫秒再啟用下一個區塊。寫 0 表示立即。（2026-10-24 已修正：原本未寫時會變成 0，現在未寫為 1200。）

quiz-next-label繼續 ▶繼續按鈕文字，只在 manual-next 時使用。
manual-alignright繼續按鈕的位置，與手動推進共用此屬性。

4. 三種推進方式詳解

4.1 自動：next 加 next-interval

<info-region id="a" active="true" next="b">A</info-region>
<info-region id="b" next="c" next-interval="1200">B</info-region>
<info-region id="c">C</info-region>

a 啟用後等預設的 500 毫秒啟用 b，b 再等 1200 毫秒啟用 c。實測時間間隔與設定值吻合。預設值可用 InfoRegionConfig.defaultInterval 全站修改。

注意：next-interval="0" 不會變成立即，而是退回預設的 500 毫秒（實測 b 到 c 相隔 503 毫秒）。原因是程式用「值為 0 就視為沒寫」來判斷。要近乎立即請寫 1。countdown="0" 同理，會變成 2000。

4.2 倒數：countdown

<info-region id="a" active="true" countdown="3000" countdown-position="top"
             countdown-color="yellow" next="b">先讀這一段，3 秒後自動下一段</info-region>
<info-region id="b" countdown next="c">只寫 countdown 就是 2 秒</info-region>
<info-region id="c">結束</info-region>
  • 倒數條是區塊內的一個絕對定位的細條，從滿寬線性縮短到 0，時間到才啟用 next。
  • 條的顏色預設跟區塊的 color，可用 countdown-color 改。
  • countdown 只在自動鏈中有效。區塊若同時有 manual，手動優先（見第 2 節）。

4.3 手動：manual

<info-region id="a" active="true" manual next="b"
             manual-label="我讀完了" manual-color="special" manual-align="center">
  內容
</info-region>
<info-region id="b">下一段</info-region>
  • 按下按鈕後，按鈕先播放約 0.18 秒的離場動畫，動畫結束才啟用 next。按鈕之後會移除，不會重複出現。
  • 按鈕固定字體是 0.85rem，內距 6px 16px，這是元件寫死的值，要改請用第 13 節的樣式覆寫。
  • manual 沒有搭配 next 時，沒有按鈕。這不是錯誤提示，而是靜默地什麼都不做。

4.4 用程式推進

InfoRegion.activate('b');          // 啟用 id 為 b 的區塊
document.getElementById('b').activate();   // 同上
document.getElementById('b').reset();      // 還原成隱藏

其他推進方式都沒有觸發時，可以靠這個。例如在 global-progress 群組中，由你自己的按鈕或事件決定何時顯示下一段。

5. 邊框系統

預設只有左邊有一條 4px 的實線，顏色是該區塊的 color；其他三邊寬度為 0（不顯示）。每一邊的寬度與樣式可獨立設定，顏色一律跟 color。

5.1 寬度的決定順序（每一邊各自判斷）

  1. 該邊的屬性，例如 border-top-width。
  2. border-width 屬性（四邊共用）。
  3. 全域設定 InfoRegionConfig.borderTopWidth 等單邊設定。
  4. 全域設定 InfoRegionConfig.borderAllWidth。
  5. 以上都沒有時：左邊用 InfoRegionConfig.borderWidth（預設 4），其他邊為 0。

寬度會用 parseInt 轉成整數（2px 也會被解讀為 2），結果小於等於 0 的那一邊不顯示。樣式的順序相同：單邊屬性、border-style、全域單邊樣式、全域 borderStyle、最後是 solid。

5.2 範例與實測結果

寫法結果
color="orange"只有左邊 4px 實線，橘色。
border-width="2" border-style="dashed"四邊都是 2px 虛線，顏色是預設的 sky。
border-top-width="3"左邊 4px（預設）加上方 3px，其餘 0。
border-width="0"四邊全部沒有邊框。
border-width="0" border-top-width="6"只有上邊 6px。單邊屬性優先於全邊屬性。
說明：邊框在區塊被啟用時套用；啟用中修改 color 或任何 border-* 屬性，會立即重新套用。圓角由全域設定 borderRadius（預設 0 6px 6px 0）決定，沒有單一區塊的屬性可以改，要個別調整請在該區塊加 style="border-radius: ..."。
注意：ir-gold 區塊用 !important 強制四邊邊框與圓角，邊框屬性對它無效。

6. 金箔特別版：ir-gold

在 <info-region> 加上 class="ir-gold"，啟用後會呈現深金色漸層背景、金色邊框、淡金色文字，以及一道緩慢掃過的光。設計用意是用在步驟序列的第一步（開場）或最後一步（結尾），與中間的普通步驟明顯區隔。

<info-region id="end" class="ir-gold">
  <h5>結尾</h5>
  <p>這是整段說明的收尾。</p>
</info-region>
  • 金色（#C9973F）是元件寫死的，color 屬性對 ir-gold 區塊的邊框與背景無效。
  • 掃光是裝飾性的低不透明度動畫，區塊內其他內容會自動疊在掃光之上，不影響閱讀。
  • 倒數條仍會正常顯示在 ir-gold 區塊中。
提示：收尾區塊用 ir-gold，還有一個實用的副作用：它能被前一題的 correct-next 啟用，剛好觸發群組進度條更新到 100%，見第 9 節。

7. 測驗模式

7.1 結構

<info-region id="q1" quiz answer="c" active="true" color="sky"
             quiz-label="IELTS Speaking Part 1"
             correct-next="q1-ok" wrong-next="q1-ok" quiz-next-delay="800"
             explain="補述用法的 <b>which</b> 可以代替前句，導出原因。"
             show-retry>
  <p>Traffic around my area can be pretty bad, ________ I tend to leave home early.</p>
  <ir-choices layout="column">
    <ir-choice value="a">except for</ir-choice>
    <ir-choice value="b">as a result</ir-choice>
    <ir-choice value="c">which is why</ir-choice>
  </ir-choices>
</info-region>
  • <ir-choices> 預設兩欄排列，加 layout="column" 變成單欄。
  • 每個 <ir-choice> 的 value 對應 answer。選項前會自動插入字母圈 A、B、C……最多 16 個（到 P），超過則改為數字。
  • 選項自動具有 role="button" 與 tabindex="0"，可用鍵盤 Tab 聚焦，Enter 或空白鍵作答。

7.2 答題後發生的事

  1. 所有選項被鎖定（加上 disabled 屬性），不能再選。
  2. 被點選的選項標上狀態：答對為 state="correct"（綠）、答錯為 state="wrong"（紅）。
  3. 答錯時，正確選項標上 state="reveal"（淡綠），讓使用者看到正解。
  4. 在區塊底部淡入解說框：開頭是 correct-msg 或 wrong-msg，接一個全形空格，再接 explain 的內容。
  5. 若有 show-retry，同時顯示重試按鈕。
  6. 若所在群組有計分，通知群組記錄結果（第 9 節）。
  7. 決定下一步：答對看 correct-next，答錯看 wrong-next。有 id 時：沒有 manual-next 就等 quiz-next-delay 毫秒後自動啟用；有 manual-next 就顯示繼續按鈕。該 id 沒寫時，這題就是終點，不推進。

7.3 重試

  • 按下重試後，選項、解說框、按鈕列全部還原，可以重新作答，同一個區塊原地重來。
  • 若同時設了自動跳題，下一個區塊仍然會在延遲後出現，不會因為重試而取消。所以 show-retry 搭配自動跳題時，重試對「已經出現的下一個區塊」沒有影響。要強迫使用者答對才能繼續，請讓 wrong-next 不寫、只寫 correct-next。
  • 重試不會取消已記錄的分數。計分規則見第 9 節。

7.4 ir-choice 的字體與內距

選項的字體與內距可以在三個位置設定，優先順序：<ir-choice> 自己的屬性 大於 所在 <info-region> 的屬性 大於 InfoRegionConfig.choiceFontSize 與 choicePadding。

屬性單位處理說明
choice-font-size純數字自動補 rem；已有單位則原樣使用同時決定字母圈的大小：圈的直徑約為字體的 23.2 倍 px 值（字體 1rem 時約 23px），字母字體約為選項字體的 0.79 倍。
choice-padding原樣套用，需自己寫單位例如 4px 8px。
已知問題：choice-font-size 請只用不帶單位的數字或 rem。 字母圈的尺寸是把數字當成 rem 去換算的，不看單位。我實測 choice-font-size="16px" 時，選項文字是 16px，但字母圈被撐成 371px 寬，版面完全跑掉。0.8rem、1.2、1.125rem 都正常。

7.5 顏色對測驗的影響

  • 區塊的 color 決定左邊框顏色，以及「繼續」按鈕的顏色。
  • 答對綠色（safe）與答錯紅色（warning）是寫死的，不受 color 影響。
  • 重試按鈕顏色用 retry-color，預設紅色。

8. info-region-group 群組

把多個 <info-region> 放進群組，就能一起控制：開始與重設按鈕、橫向排版、逐一顯示、全域進度條、計分板。群組會找出自己內部所有層級的 <info-region>，順序就是文件順序。

8.2 開始與重設

  • 開始：先重設整個群組（清空分數、所有區塊還原隱藏、進度條歸零），然後啟用第一個區塊；若有 cascade-interval，則改成依序啟用全部。
  • 重設：清空分數與答題記錄、還原所有區塊、進度條歸零、百分比歸零並淡出。
  • 群組內的區塊不會在載入時自動展開，除非該區塊自己寫了 active="true"，或群組有 auto-start。

9. 群組進度條與計分板的精確規則

9.1 進度條（global-progress）

群組內容進度的算法
沒有任何 quiz-item 區塊已啟用的區塊數 除以 群組內全部區塊數。
有 quiz-item 區塊只統計帶 quiz-item 的區塊：已答對的題數 除以 quiz-item 區塊總數。答錯重試不會讓進度倒退，答對後也不會因再重試而扣回。
已知問題：進度條只在某個區塊的 active 屬性被寫入時才會重新計算，答題本身不會觸發。 我實測：兩題的群組，第二題（最後一題）答對後沒有任何區塊再被啟用，進度條停在 50%。解法是讓最後一題的 correct-next 指向一個收尾區塊（例如 ir-gold 的結語），啟用它的那一刻就會更新，實測達到 100%。收尾區塊不要加 quiz-item，否則會被算進題數。
  • 進度條與百分比的動畫時間由 InfoRegionConfig.progressTransition（預設 400 毫秒）控制。
  • 進度條的監看範圍是群組建立時就存在的區塊，之後動態加入的區塊不會被監看。

9.2 計分板（show-score）

欄位規則
答對答對的題數，每一題最多算一次，即使重試再答對也不會重複加。
答錯一題在「尚未答對」之前，每答錯一次就加 1（包含重試後再錯）。一題一旦答對，之後再答錯不會增加。
總題數答對加答錯的總和，也就是作答次數，並不是題目的數量。

實測範例（兩題，皆有重試）：第一題先答錯，計分板為 0 / 1 / 1；重試後答對為 1 / 1 / 2；第二題答對為 2 / 1 / 3。

注意：群組內的測驗區塊一定要有各自不同的 id。 計分以 id 去重，沒有 id 的區塊都被當成同一個空字串 id。實測兩題都沒寫 id、都答對，答對只算 1。測驗區塊不在群組內時，沒有計分也沒有進度。
說明：InfoRegion.resetAll() 只重設區塊，不會清空群組的計分與進度。要完整重來，請用群組的 reset() 或 start()，或按群組的重設按鈕。

/* 行距：元件固定為 1.75，沒有設定鍵 */

14. 與 practice-tracker 搭配，以及你第一課頁面的實例

14.1 完成通知

info-region 不發事件，所以要讓 practice-tracker 知道「某段已讀完或測驗完成」，用 MutationObserver 觀察最後一個區塊的 active 屬性，等它被啟用就呼叫 markDone。

最後一個區塊被啟用，就標記 section 完成
const last = document.getElementById('q-final');
new MutationObserver(() => {
  if (last.getAttribute('active') === 'true' && window.PracticeTracker) {
    window.PracticeTracker.markDone('ex-quiz');
  }
}).observe(last, { attributes: true, attributeFilter: ['active'] });

若 section 本身有內建的標記完成按鈕（practice-tracker 的 data-btn-text），也可以不用上面的程式，讓使用者自己按。

14.2 你第一課頁面的測驗，逐項拆解

<info-region id="s1-q1" quiz answer="c" correct-next="s1-q1-done" active="true" color="sky"
    quiz-label="IELTS Speaking Part 1" border-width="1px" border-style="dashed"
    choice-font-size="0.8rem" choice-padding="5px"
    explain="補述用法的主格關代which代替前句(結果)，導出原因" show-retry>
  ...
  <ir-choices layout="column">
    <ir-choice value="a">except for</ir-choice>
    <ir-choice value="b">as a result</ir-choice>
    <ir-choice value="c">which is why</ir-choice>
  </ir-choices>
</info-region>

<info-region id="s1-q1-done" color="safe" next="s1-q1-extra1" manual>
  逗號 + which 經常接下列動詞：shows, indicates, represents, symbolizes
</info-region>
<info-region id="s1-q1-extra1" color="special"> ...例句... </info-region>
寫法實際效果
quiz answer="c"測驗模式，正確答案是 value 為 c 的選項。
correct-next="s1-q1-done"，沒有 wrong-next答對才啟用 s1-q1-done；答錯則停在這題。因為有 show-retry，使用者可以重試，這個組合是合理的。
沒有 quiz-next-delay答對後等預設的 1200 毫秒，下一個區塊才出現，讓使用者先看解說。想要立即出現，寫 quiz-next-delay="0"。
border-width="1px" border-style="dashed"四邊 1px 虛線（1px 會被解讀為 1）。
choice-font-size="0.8rem"單位是 rem，所以字母圈正常縮小，沒有 px 問題。
s1-q1-done 的 manual next="s1-q1-extra1"顯示「▶ 下一步」按鈕，按了才出現延伸例句。
s1-q1-done 的 color="safe"綠色邊框；按鈕也是綠色。
提示：你的頁面把兩欄的內容分別放在兩個 <div class="col">，區塊之間用 next 跨欄串連，沒有問題。next 只認 id，與區塊在 DOM 的位置無關。

15. 疑難排解

症狀最可能的原因怎麼處理
整頁什麼都沒出現所有區塊都是隱藏狀態，沒有任何一個被啟用。第一個區塊加 active="true"；或用群組的開始按鈕、auto-start；或程式呼叫 activate()。
第一個區塊出現，後面都沒跟著出現1) 漏寫 next；2) next 的 id 拼錯（console 有警告）；3) 區塊在 global-progress 或 cascade-interval 的群組裡，next 鏈被停用。檢查 id；global-progress 群組請改用 cascade-interval、manual、quiz。
manual 區塊沒有按鈕沒有寫 next。加上 next。
答錯之後整個流程停住沒寫 wrong-next，答錯就是終點。寫 wrong-next（可與 correct-next 相同），或用 show-retry 讓使用者重試。
答對後下一題出現得太慢或太快quiz-next-delay 預設 1200 毫秒。依需要調整，立即請寫 quiz-next-delay="0"。
選項前的字母圈大得離譜choice-font-size 用了 px 單位。改成不帶單位的數字或 rem。

16. 已知問題與限制（彙整）

以下都是我實際執行驗證過的行為，沒有一項是猜測。這些是元件現有的狀態，我沒有修改你的 info-region.js。

編號問題影響暫時的做法
1next-interval="0" 與 countdown="0" 會退回預設值（500 與 2000）。無法用 0 表示立即。next-interval 寫 1。
2群組進度條只在區塊 active 被寫入時更新，答題不會觸發。最後一題答對後，進度條停在上一次的數值。最後一題的 correct-next 指向收尾區塊。
3計分板「總題數」實為作答次數。數字比題目數多。知道即可，或另做自己的題數顯示。
4計分以 id 去重，沒有 id 的測驗區塊互相衝突。答對題數少算。每個測驗區塊都寫 id。
5choice-font-size 用 px 單位時，字母圈被當成 rem 換算。字母圈變成數百 px。只用數字或 rem。
6global-progress 群組內，區塊的 next 與 countdown 被停用。只有第一個區塊亮起。改用 cascade-interval、manual、quiz，或程式啟用。
7初始 active="true" 的區塊，啟動流程執行兩次。無實際影響，各流程有防重複。知道即可。
8不發出任何自訂事件。無法被其他元件通知。用 MutationObserver 觀察 active。
9行距固定 1.75；多處字體小於 1rem；多處 rgba 透明度低於 0.78。與你的版面規範不符。第 13 節的覆寫範本處理行距與字體。
10InfoRegion.resetAll() 不重設群組計分與進度。重設不完整。用群組的 reset()。
11啟用狀態下區塊最大高度 4000px。超長內容被裁切。拆成多個區塊。
12explain、correct-msg、wrong-msg 以 innerHTML 寫入。內容中的 HTML 會被執行解析。只放自己撰寫的內容，不要放使用者輸入。
13cascadeInterval 全域設定只被「開始」按鈕讀取，區塊判斷只看屬性（讀碼所得）。只靠全域設定時，next 鏈與逐一顯示同時運作。一律用 cascade-interval 屬性。
